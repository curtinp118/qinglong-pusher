# 配置与使用

[返回仓库首页](../README.md)

## 安装与配置

1. 获取维护者发布的 `qinglong-pusher.conf` 订阅地址，无需部署服务器。
2. 将该地址添加到 QX 重写引用并启用。
3. 启用 QX 重写与 MitM，安装并信任 QX 证书；在 iPhone Safari 打开 `https://qlpush.com/`。
4. 在控制台「设置 → 青龙面板」填写 **HTTPS** 地址、Client ID、Client Secret，并在青龙「系统设置 → 应用设置」授予环境变量权限。配置仅保存到本机 QX，Client Secret 不回显。
5. 新建 App，例如「签到 App」。填写它的环境变量名、URL 正则表达式、请求头名（如 `cookie` 或 `authorization`）。
6. 点击「预览 JS」只检查生成的脚本，不保存配置；可返回继续编辑，或在面板中「确认保存」。编辑页只预览，不提前保存。预览面板的「返回编辑」、叉叉与遮罩都只关闭；只有「确认保存」写入配置。保存后点击「一键导入 QX」。内容未修改时不重复显示确认保存按钮。开发模式使用「确认保存到预览列表」，刷新后清除，不会写入 QX。
7. 新建第二个 App，重复操作。两份订阅地址和 QX 资源标签各不相同，不会替换彼此。
8. 打开对应 App 触发请求。脚本直接向青龙同步；页面重新加载或重新选择已加载的 App 时展示其记录，实时状态请刷新页面。

首次从旧版迁移：关闭旧抓包重写，在本控制台重新配置青龙。项目不读取或迁移 BoxJS 设置，也不依赖其运行。

## App 独立配置

- 每个 App 有稳定 ID、名称、最多 10 条变量规则、独立订阅地址、资源标签、同步锁及最近结果。最多 20 个 App。
- 各应用直接导入本机 9999 端口的 `/qinglong-pusher/scripts/<App ID>.js`，文件头包含 `[rewrite_local]` 与 `[MITM]`，由 QX 资源解析器提取规则。脚本绑定 App ID，只读取该 App 的本机规则。
- 资源标签采用应用名称，默认开启资源解析器。App 改名不变更 JS 订阅地址；已有 QX 标签需要重新导入或手动更名。
- 修改 App A 不改变 App B 的订阅内容。修改 URL 后，仅需重新导入或刷新 A 的资源。
- 停用规则并确认保存后，会阻止之后的推送。删除 App 后旧脚本不再执行，旧订阅返回空配置；还需手动移除或刷新 QX 资源以清理旧 MitM 域名。不删除青龙已有变量，也不能撤回正在执行的请求。
- **不同 App 不允许相同青龙变量名，也不允许抓取 URL 模式重叠**。前者可能互相覆盖青龙数据，后者可能受 QX 首条重写匹配影响。正则交集不做完整求解：只有固定域名或固定路径前缀可证明独立时才允许跨 App 保存；无法证明时保守拒绝，可能拒绝实际上不重叠的复杂规则。
- 多个 App 共用现有青龙面板认证，但规则、资源、锁和结果分离。目前不支持每 App 独立面板或同名多账号。
- QX preferences 没有原子锁；并发抓取只使用尽力而为的短租约，不能保证严格 exactly-once。多 Safari 标签同时编辑也可能覆盖，请单页面操作。

## 请求头保存方式

每条变量规则可选择「单个请求头」或「全部请求头 · JSON」，旧规则默认保持单个请求头模式。

- 单个请求头：填写 Cookie、Authorization 等头名称，只将对应值写入青龙变量。
- 全部请求头：无需填写头名称，将 QX 提供的全部字符串请求头序列化为紧凑 JSON 对象字符串，作为一个青龙变量的值。保留 QX 返回的字段名称大小写和原值，不拆分 Cookie，不嵌套在 `headers` 字段中。
- QX 未提供的头不会补造；没有可用请求头时不推送。全部请求头可能包含 Cookie、令牌等敏感数据，仅用于同步到配置的青龙面板，不写入本地配置、状态或日志。
- 保存模式修改后，更新该应用的 QX JS 资源缓存，确保执行新版抓取脚本。

## 数据与安全

- 不向分发服务发送捕获值、青龙凭据或令牌；不写日志、数据库、Cookie 缓存或 token 缓存。
- 自动推送必然需要 QX 在内存中读取命中的请求头，再直接发送到授权青龙。除目标青龙变量外，本项目不持久化捕获值。
- 面板认证保存在独立 QX preference `qinglong_pusher_panel_v1`。状态接口仅返回地址、Client ID 与是否已有密钥，不返回密钥。QX preferences 不是加密保险箱，应保护设备及其备份。
- 同地址和 Client ID 下，密钥留空保留原值；更换地址或 ID 必须重填密钥。「清除面板配置」停止后续同步，不删除 App 或青龙变量。保存只验证格式，不验证网络连通性。
- 开发预览禁用凭据输入，Node 服务不提供认证保存接口；不要向预览服务提交真实认证信息。
- 规则以明文存储于 QX preferences。不要填写带真实令牌的路径、Cookie 值或密钥；请求头字段只填名称。
- URL 使用以 `^` 开头的正则，不加 `/…/g` 等定界符和标志。协议支持 `http`、`https`、`https?`，域名必须固定且点写作 `\.`；支持转义斜杠。路径支持 `.*`、字符类、数字量词和 `(?:a|b)` 分组，可匹配查询参数。最长 500 字符，支持分组后 `?` 表示可选；禁止空白、顶层分支、环视、反向引用及分组后 `*`、`+`、`{n}` 重复量词。不保证所有复杂正则的性能，请保持规则简短。
- 青龙只允许 HTTPS，禁用重定向和自动 Cookie，并保持证书校验开启；接口响应和失败详情不写入日志。相同变量值不重复写入，更新保留 remarks/labels；多个同名变量时拒绝覆盖。
- QX 重写资源刷新是否经过本地拦截、请求头/请求体可用性、Universal Link 导入和 MitM 信任均需要实机验证。证书固定的 App 可能无法捕获，本项目不绕过此限制。

## 常见问题

| 问题 | 处理方式 |
| :--- | :--- |
| 入口重写无法下载 | 检查发布地址和网络可达性；入口必须引用已发布的静态 `qx/local.js` |
| 页面显示「预览」 | 当前打开的是开发预览；导入入口重写后，在启用 QX 的 iPhone 上打开 `https://qlpush.com/` |
| 页面显示已配置，但没有推送 | 已配置仅表示存在认证设置，不代表青龙连通；检查 HTTPS 证书、应用权限、目标请求是否命中 |
| 修改 URL 后未触发 | 刷新当前 App 的 QX 重写资源，确认新域名已加入 MitM |
| 新 App 无法保存 | 检查变量名是否与其他 App 重复、URL 范围是否重叠，以及每 App 10 条规则、总共 20 个 App 的限制 |
| 删除后仍有 MitM 域名 | 手动移除或刷新对应 QX 资源；删除配置不会删除青龙已有变量 |

## URL 正则示例

```text
^https://api\.example\.com/user/.*$
^https?://api\.example\.com/(?:user|account)/\d+$
^https://api\.example\.com/user/info\?page=\d+$
```

域名用于自动生成 MitM hostname，路径正则直接写入 JS 头部的 `[rewrite_local]`，QX 抓取脚本也使用同一条表达式。不要在查询参数中填真实令牌。旧版通配 URL 仍可读取；打开编辑页时转成等价正则，保存后使用正则格式。单独的 `*` 在新输入中是正则量词，不是原来的任意字符通配。

## 一键导入

已保存应用可在列表直接点击「导入 QX」，也可在生成结果中点击「一键导入 QX」。使用 QX 官方 Universal Link 携带 `rewrite_remote` 订阅，跳转后按 QX 提示确认；网页不能绕过客户端确认或判断是否已安装成功。每个应用保持独立资源标签。

开发预览中的应用导入按钮禁用，不会把未保存到手机的应用当作可用资源导入。控制台不重复展示入口安装步骤，首次安装请按发布文档获取正式入口。未跳转时使用 iPhone Safari，或展开 `规则与 JS 订阅地址` 手动复制到 QX。

## 测试青龙连接

在「设置 → 青龙面板」保存配置后，点击「测试连接」。QX 使用已保存凭据直接请求认证接口，再只读访问环境变量接口。

- 灰灯：未测试或配置发生变化；黄灯：测试中；绿灯：认证和变量读取成功；红灯：失败并显示脱敏原因。
- 测试不新增或修改变量，不验证写入权限，不持久化访问令牌或环境变量响应。
- 成功状态只代表该次测试，显示测试时间，5 分钟后失效。编辑、保存、清除配置或刷新页面都会重置状态。
- 有未保存修改时必须先保存；测试期间禁用编辑与重复操作。8 秒网络预算，超时可重试。
- 开发预览禁用测试按钮，不代理真实认证。QX 入口重写更新后需刷新入口资源，才能使用 `/api/panel/test`。

## PWA：添加到主屏幕

先在 QX 安装入口并启用重写、MitM，使用 iPhone Safari 打开 `https://qlpush.com/`，再选择「分享 → 添加到主屏幕」。主屏幕启动使用独立窗口；不要把电脑 localhost 预览地址作为正式应用安装。

设置页提供安装说明。支持安装事件的浏览器可显示安装按钮；iOS Safari 通常需要手动使用分享菜单，网页不能代替用户确认。

- Service Worker 只缓存页面、样式、前端脚本与 manifest；API、凭据、应用配置、`.conf` 和抓取 JS 均不缓存。
- 离线可显示界面，但无法读取本机 API 时禁止编辑；测试连接、保存和同步仍需 QX 入口正常运行。
- 缓存按资源内容版本切换。设置页出现「启用新版本」时，先保存编辑内容，确认更新后按提示刷新。不会自动刷新丢弃输入。
- 主屏幕窗口与 Safari 的网站存储可能隔离。这里的配置由 QX preferences 管理，不依赖浏览器缓存；两者都必须能够经过 QX 拦截。
- iOS 的主屏幕图标、安装、受信任 MitM 下 Service Worker 行为以及 QX 内部资源下载仍需实机验收。注册失败会显示说明，不影响在线界面。图标使用内嵌 PNG，若具体 iOS 版本不支持该图标形式，可能使用系统生成图标。

## 切换到 JS 资源导入

更新 QX 入口脚本 `qx/local.js` 缓存，刷新控制台，再从应用列表重新导入。导入地址应为 `http://127.0.0.1:9999/qinglong-pusher/scripts/<App ID>.js`，资源标签为应用名称，资源解析器默认开启。移除原来的应用 `.conf` 引用，避免重复规则；入口 `qinglong-pusher.conf` 需要保留。

预览显示完整 JS，包含规则头部与绑定当前 App 的执行代码。更改 URL 或停用规则后，刷新该应用的 QX 资源；删除后 JS 地址返回无规则的空操作脚本。

手动访问 JS 有内容并不能确定 QX 资源解析、更新及执行时均可下载。503 的具体来源尚未确认，此导入格式调整仍需在 iPhone 实测，不能视为已验证的网络故障修复。

## 本地后端与更新

入口 `qinglong-pusher.conf` 同时包含 `[rewrite_local]`、`[mitm]` 和 `[http_backend]`，不再单独分发后端 conf。QX 的重写引用不保证加载主配置段：如本地服务未启动，将同一 conf 中后端配置行合并到主配置 `[http_backend]` 下，保留其他配置。

应用 JS 和其中的脚本地址均指向 `127.0.0.1:9999`。这样资源下载不再依赖 qlpush.com 的 MitM 重写。服务未启用时会连接失败，不会回退到公网域名。只提供生成脚本，不暴露认证和状态 API。实际 QX 版本的后端加载与脚本更新仍需实机验证。

PWA 在启动、回到前台、网络恢复以及前台每五分钟检查更新；自动检查至少间隔一分钟。设置内可手动检查。发现新版后提示确认，未保存修改或正在提交时禁止激活；确认后自动刷新。其他窗口激活更新不会强制刷新当前编辑。先更新 QX 入口脚本缓存，再检查 PWA；后端逻辑变更还需更新后端脚本。
